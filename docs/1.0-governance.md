# codex-mcp 1.0 Governance Baseline

## Goals

Version 1.0 is an intentional breaking release. Old commands, config, OAuth state, and compatibility entry points are no longer runtime contracts. The first upgrade requires setup again and invalidates existing OAuth sessions.

Freeze contracts first, clean CLI/config/runtime lifecycles, add black-box acceptance coverage, then upgrade local management to an independent Controller and complete Console. Do not discard verified foundations or security boundaries just to clean historical code.

## 1.0 user commands

```text
codex-mcp setup
codex-mcp start [--local] [--no-tunnel] [--tunnel-logs] [--root DIR]
codex-mcp stop
codex-mcp restart
codex-mcp status [--json]
codex-mcp project list
codex-mcp project add [DIR]
codex-mcp project remove [ID|NAME|DIR]
codex-mcp project info [ID|NAME|DIR]
codex-mcp logs [--follow] [--lines N]
codex-mcp doctor [--fix]
codex-mcp auth
codex-mcp update
codex-mcp help
codex-mcp version
```

Daemon/controller are internal process entries, absent from user help/contracts. Bare codex-mcp shows help; start is explicit.

## Removed historical entry points

- tunnel: public configuration now uses setup.
- exit: stop services with stop, deactivate projects with project remove.
- serve / --foreground: daemon-managed start; debug with --local.
- Context-dependent -f: only logs --follow remains.
- Old flat public-access fields: no automatic config migration.
- workspaces / permissions: neither read nor silently ignored.
- Old approve/pending flow/endpoints: only router-native authorization remains.
- Removed tool aliases/action snapshots: rescan the 1.0 tools in ChatGPT.

## Config and state

Only current tagged publicAccess, capabilities, clientCapabilities, and ui models are accepted. Old config requires a clear setup-required error or explicit reset, never treating invalid config as empty.

No legacy reads for oauth-state.json, daemon.json, projects.json, session-bindings.json. Report corruption; only missing files mean empty state. Persisted files use exact schemas plus schemaVersion.

Daemon HTTP control separately uses controlApiVersion: 1. Within a major, required fields are strict but new unknown fields are allowed for rolling 1.0.x updates. Reject incompatible protocol versions.

## Security boundaries to preserve

- OAuth PKCE/private_key_jwt/resource binding/credential generations.
- Safe HTTP SSRF, DNS rebinding, redirects, sizes, timeouts.
- Canonical paths, symlink containment, project isolation.
- Loopback plus random-token daemon control.
- Process owner scopes, tree shutdown, output budgets.
- Tunnel candidates, DNS cutover, public probes, compensation.
- Private atomic writes and sensitive-file permissions.

## Controller / Web Console

Console is the complete local GUI. Controller is independent: stop closes Runtime/Tunnel/project runtimes, leaving Controller/page able to start again. Setup/auth/doctor/update/project/logs have Web equivalents.

Controller listens on loopback separately from public MCP/OAuth. Browser mutations require a random HttpOnly SameSite=Strict session cookie, same-origin Origin, and CSRF. CLI uses a separate random controller.json token never exposed to browsers. Pages have per-response nonce CSP; management/logs are not cached. Operations/SSE expose progress/results/cancellation. Cloudflare authorization output remains available if browser opening fails.

## Lifecycle commit points

- Ordinary start/project add reuse intent; explicit mode flags switch it. Validate config/password before stopping for a switch/restart.
- One lock serializes start/stop/restart/offline deactivation/public setup.
- Startup CLI retains its child until service startup, public probe, and state commit finish. Timeout/cancellation cleans this child; startup IPC disconnect cancels uncommitted instances.
- Tunnel registration: 180 seconds. Public probe: one 30-second budget. CLI startup: at most 300 seconds, followed by bounded cleanup.
- Publish project/binding/OAuth memory state only after private atomic persistence. Commit replay revocation before returning the protocol error.
- Persist lastSeenAt at most every ten minutes; bind/unbind/invalidate commit immediately, avoiding full binding-file rewrites for every tool call.
- Multi-project daemon does not create a default cwd ProjectContext/process pool. Explicit conversation bindings lazily load runtimes.

## Compatibility

Remove human-readable cloudflared table parsing, unused default skill discovery, and batch deactivation. Keep SDK legacy: stateless required by current protocols, ChatGPT widget metadata, OAuth DCR/CIMD, and Windows file replacement recovery. These are not old config migrations.

## Acceptance evidence

- cli-contract.test.js: built CLI, removed entries, corrupt state, persistence, writable Console, CSRF/Host, restart after stop.
- lifecycle.test.js: timeout/parent disconnect, Tunnel exit/bounded recovery, rotation.
- mcp-tools.test.js: real HTTP calls to 15 tools, writes, project/session/process/skill/downstream isolation.
- oauth.test.js: HTTP OAuth/PKCE/rotation/revocation/generations/private_key_jwt/write-failure recovery.
- security.test.js: SSRF/socket DNS, HTTP budgets, exact probes, paths/symlinks, process trees/output caps.

Local tests do not prove a ChatGPT account connector is enabled or replace actual Cloudflare switching/cross-platform CI. Validate target platforms and real ChatGPT calls before claiming connector acceptance.
